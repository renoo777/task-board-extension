# 任务台 · 浏览器扩展 v0.24.0

点浏览器右上角图标弹出来的轻量任务台：今天聚焦、按日期或项目组织、拖拽流转状态、不想干的事先挂起。

数据存在你自己电脑的浏览器里，**默认不发任何网络请求**。v0.6.0 起可以可选地接上飞书多维表格做备份和外部编辑（不配就是纯本地，见第六节）。
v0.16.0 起可以可选地打开 **AI 能力**（**默认关**）——选「仅本机」时它跑在浏览器自带的小模型上，**不联网、不花钱、也不出这台电脑**；只有你自己选了云端、填了自己的 Key 之后，才会有内容发到**你自己填的那个地址**（见第十一节）。

> **v0.15.0 把设置页和弹窗里的介绍文字全清了 —— 介绍统一收进这份文档。**
> ① **设置页只剩控件**：删掉了整节「说明」（状态色图例 + 用法清单）、每节标题下的说明段、以及飞书与球两块折叠起来的原理段落。留下来的只有**控件**、**后果**和**风险提醒**（App Secret 明文警告、开关关掉会怎样这类「你要付出什么代价」的话）。
> ② **弹窗里那个按 `?` 弹出的速查浮层删了** —— 界面里不再有任何说明层，键位表在本文档第三节。
> ③ **设置页左侧导航从 5 项减到 4 项**（项目 / 飞书同步 / 桌面悬浮球 / 数据）。

> **v0.14.0 把球砍到只剩一层 —— 点一下就是「记一笔」，不再有滑杆、不再有迷你列表。**
> ① **它长什么样**：贴着你屏幕**右边缘、垂直居中**的一颗 32px 蓝色小球，球面上是**未完成数**。平时**半透明 0.65**，鼠标移上去才变实心 —— 不挡网页正文。球旁边**不再有任何东西**：悬停只是把球点亮，不会冒出多余的按钮 —— 原来那个「悬停才露的小齿轮」（进设置）在 v0.24.0 尾被删掉了，见下面的沿革。
> ② **点它 = 记一笔**：输入框**当场**在球旁边出现（球自己一动不动），打完字按回车就存下了（球上闪一个白勾）。**一共一层** —— 不滑出轨道、不展开迷你列表、不用再点第二次。
> ③ **想拖就拖**：按住球拖到任何位置，松手**自动吸附到最近的那条边**（左右按**球心**过中线判定）。位置和吸附的边存在浏览器里，**所有网站共用**。全屏看视频 / 看图片时它自己藏起来。
> ④ **「打开网页它就在」只能靠声明式 content script，点图标换不来** —— 官方原文：只要设了 `default_popup`，`action.onClicked` 就**不会触发**，因此「点一下图标直接出球」在浏览器层面根本做不到。**代价是：重载扩展之后，之前就已经开着的标签页要刷新（F5）一次才会长出球**（声明式 content script 只在「页面被打开时」注入，不会回溯）。
> ⑤ **代价（说清楚）**：它只活在网页上 —— 切到桌面、微信、Excel 就看不见了。想要「任何界面抬头都在」，那是**桌面程序那颗球**（可选，见第七节）。两条路读的是**同一份数据**，装哪个都行，不装也完全不影响别的功能。
> ⑥ **弹窗里那个「浮到桌面」按钮已经删了** —— 它就是「点两次」的来源：点图标弹窗（第一次）+ 点它（第二次）＝ 才见到东西。

| v0.24.0 | **球可以换成「吉祥物」形态（可选 · 默认开）**：老大要的是「上班上一整天，能活跃一下气氛」——球换成会转头的小家伙，鼠标靠近它朝鼠标看、点一下看你一眼、连戳几下会晕、存下任务笑一下。机制来自开源项目 page-mascot（MIT）：**两张 3×3 雪碧图 + `background-size:300%` + `background-position`** 切九个朝向与九个反应，没有 canvas / WebGL / 引擎。★ 三处**故意跟上游不一样**：① 零依赖原生重写（两个宿主都塞不进 React，为一个小人引框架不值）；② `pointermove` 用 rAF 合并 + 缓存 rect（我们要注入到**每一个**网页里，不能每来一个事件就强制一次同步布局）；③ 死区随尺寸缩放 `max(22, size*0.5)`（上游写死 70px 是按它自己 140px 的组件调的）。★ 故意**少**一条：不挂 `scroll` 监听 —— 两个宿主都是 `position:fixed`，滚动不改它的视口坐标，挂了纯属白丢强制布局。★ 两个不报错的坑：a. content script 用 `background-image` 引扩展内图片**必须配 `web_accessible_resources`**，不配就整片 404 而**页面里一个报错都没有**，球变成一个空壳；b. ### 几条被反复问到的设计决定

> 这些都是「**为什么不能那样做**」的答案，改样式 / 改交互之前先看一眼 —— 每一条都是踩过之后才定下来的。

- **吉祥物为什么默认是「开」**（v0.24.0）：**先纠正一个我自己写反过的地方** ——
  `ballpage.js` 里那个 `mc: { on: false, ... }` **不是「默认关」**，它是「**还不知道**，先别挂」
  （与网页球开关同一条防闪规则：乐观写 `true` 的话，开关真关着时会先挂一帧再摘掉，那一帧
  闪现比晚一拍出现难看得多）。**真正的默认值在 `mascot.js` 的 `readConfig` 里**：
  `on: v.on !== false` —— **没存过就是开**，与 `readWb` 逐字一致。
  ★ 为什么选「开」：这两个开关问的是同一件事（要不要在别人的网页上多画点东西），默认值不一致就会
  出现「网页球默认开着、吉祥物默认关着」= 用户看到半截功能，还得自己去找那个开关。老大要它
  的原话也是「上班上一整天，能活跃一下气氛」。
  ★ 代价照实说：它比圆球大得多（默认 72px / 圆球 32px）而且**一直在动**（跟着鼠标转），挂在每个
  网页上等于给所有页面加一个持续吸引余光的目标 —— 所以开关就在设置页一行、**即时生效**，
  觉得吵就关掉（不用刷新已经开着的页面）。
  ★ 同源的另两条取舍：① 根元素必须 `pointer-events:none` —— 它盖住的那块网页内容还得能点，放开的话用户只会以为「这个网站坏了」（指针坐标挂在 `window` 上收，元素本身不吃点击）；② 关掉时走 `unmount()` 而不是 `display:none` —— 全局 `pointermove` 监听要跟着摘掉，否则每个网页上都白挂一个永不触发的回调。
- **为什么 `mascot.js` 存了两份（扩展 + 桌面球）**（v0.24.0）：扩展那侧是 MV3 的 content script（清单里逐个列文件、**不支持裸模块 `import`**），桌面球那侧是 Tauri 的本地页面 ——**两边没有共同的模块加载器**，物理上只能各放一份。可选方案是「打包时把同一份源码注入两个位置」，但那样**改了源码却忘了同步**就会两边行为不一致，而且不一致得**很安静**（一边跟着转、一边不转，谁也不会想到是文件不同步）。现在的做法是：源码只认 `task-board-extension/mascot.js` 这一份，改完必须跑 `_p_372_sync_mascot.py` 推过去，并且 `_test_mascot.js` 里有一条断言**逐字节比对两边** —— 不同步就是当场红。
- **转场为什么从「推圆」换成「所有颜色一起渐变」**（v0.23.0）：圆扩散是 `clip-path: circle()` 动画，而 **`clip-path` 是主线程属性** —— 每帧都要按新半径重新光栅化，成本 **∝ 覆盖面积（半径的平方）**；圆的绝对尺寸同时又涨到最大，两者相乘就是「铺到约 2/3 开始卡」。用 CDP 采**真实** rAF 帧量过：圆扩散最坏帧 **33.4ms / 4 次切换掉 20 帧**（掉帧全在动画期），而「完全不动画」的对照组是满帧 **16.8ms / 0 帧**。改成把 **62 枚主题令牌**注册成可插值的 `<color>`（`@property`）让它们各自 `transition`：最坏帧 **16.8ms / 掉帧 0**，与对照组同值 —— 这条路线的开销与覆盖面积**无关**。★ 代价说清楚：**失去「新主题从按钮那个点推出来」的方向感**，拿到的是「屏幕上所有颜色一起平滑渐变」。这是拿「有因果感的动画」换「不卡」的自觉取舍，不是没想到。
- **开关的轨道为什么必须是不透明色**（v0.23.0）：「关」态一度用半透明白当轨道，铺在白页上等于**没有轨道**；而设置页的种子数据里**六个开关全是勾着的**，只出「开」态图永远发现不了 ——专门补了两张「关」态探针图才看见。现在轨道不透明（未勾 `--sw-a` / 勾上 `--solid`），钮用 `--bg-4` 画在 `background-image` 里：**`input` 是替换元素，Chrome 不渲染它的伪元素**，所以钮只能用 `radial-gradient` 画、再用 `background-position` 平移（位移只写一处，两层一起动）。
- **为什么光晕降浓度用 `rgba(原色, .60)` 而不是「把颜色往底色混」**（v0.21.1）：两者**视觉等价**（实测平均差 **0.12**、差 >2 的像素 **0.00%**），但往底色混算出来的实色是 `#ebecf9`，通道跨度只剩 **14** —— 会被色相门当成「近中性色」**跳过**，亮色那三个 `--glow-*` 从此没人守（而那正是那条门要防的「两态只守一态」）。改 alpha 写法：rgb 部分不变、跨度仍是 22，门扫得到，浓度却真的降了。★ 与 `theme.css` 里那条「别再改回 rgba(中明度色,.7x)」不冲突：那条针对的是**颜色比底色暗**（`150,186,255`）会被读成水渍；这里是同一个浅色降浓度，且现代浏览器在 premultiplied alpha 空间插值，`rgba(c,a) → transparent` 是纯浓度衰减，不会跟底色混成脏灰。
- **为什么「用形状区分三态」而不是「把颜色调得更分开」**（v0.21.0）：三个列头状态点原来的色相是 **217° / 232° / 248°** —— 相邻只差 **15°**，在 9px 的点上人眼根本分不出，这才是「点不明显」的**物理原因**（不是「点太小」）。拉大色相差当然也行，代价是往色板里再塞一个高饱和色 —— 而 v0.20.0 刚把「一屏 2 色相」立成规则。形状不占色相预算，而且**缩小、色盲、灰度打印**三种情况下全都成立，颜色这三条一条都做不到；所以是空环 / 实心 / 对勾。★ 顺带记一个坑：对勾一度做成「实心圆里塞一个白勾」，放大 4 倍看糊成一团 ——「点」靠**面积**、「勾」靠**笔画**，勾需要的是长度不是面积，塞进小圆里是南辕北辙；改成独立对勾才读得出来。另外 `*{box-sizing:border-box}` **不匹配伪元素**（`*` 只选元素），伪元素的尺寸要显式声明，否则「勾的中心压在圆心上」这类算术会从一开始就偏。
- **配色为什么要「限色相」而不是「调淡一点」**（v0.20.0）：被反馈「花」之后量下来，问题不是审美，是三个可量化的超标 —— 一屏 **5 个色相**（紫/蓝/绿/橙/红）、每张卡 **3 个色团**、色团不透明度 **.58–.72**。第三项最致命：α 到 .7 时色团**边界清晰可见**，眼睛就把一张卡读成「三块颜色」而不是「一块有颜色的玻璃」。所以这一版不动结构、只立三条规则：① **一屏 2 个色相** —— 紫＝材质、蓝只作紫的邻近过渡（色相差 ≤15°，不构成独立色相）、橙降级成语义色（只上文字与圆点，绝不做面）、**绿只剩热力图一处**；② 三个色团的「不规则」**保留**（那是「液态」的来源，别改成 linear-gradient），但色相统一到紫蓝同区、α 砍到 .34–.44，圆心挪向边角、半径放大让三团**互相重叠** → 读成一整片；③ 层级交还给光影 —— 投影 .44→.20、圆角 20→22px、颗粒 .255→**.30**。★ 最后一条反直觉但重要：**颗粒要加不要减**，噪声越明显越不像塑料。★ 顺带记一条判据：**「低饱和」不是「淡」**，而是相邻两级的差别「看得出来但不刺眼」——新色板里三个材质色块肉眼几乎一样，那才是低饱和；调成一眼两个色就是没做到。
- **玻璃层为什么挂在卡片上、列反而让路**（v0.19.0 起，此前正好相反）：一个区域里**只允许一层玻璃** —— **玻璃叠玻璃**会让两层模糊各算各的，里层发灰发浑、状态色一起脏。v0.18.0 是让卡片让路（列当玻璃）；v0.19.0 反过来，因为卡片里要装**液态斑**和**颗粒噪点**，这两样必须长在玻璃层**自己这一侧** —— 画在下层会被 `backdrop-filter` 直接抹平。**被拖起来的那一张**这条继续成立：它离开列、悬在看板上方，本来就是独立的一层。挂起浮层与归档抽屉是同一个规则的另一面：浮层自己当玻璃，里面的卡片退回实面（用 `--card`）。
- **材质令牌为什么单独一套前缀**（`--lg-*` / `--liq-*` / `--glow-*`）：不复用 `--card` / `--glass`。后两个在设置页是**浮层实底**（`#ffffff`），语义跟「半透明玻璃」正好相反 —— 复用就会连坐：改一下卡片底，浮层的实面跟着一起变透。
- **原生 `<select>` 为什么碰不得**：它的**选项列表是操作系统画的**，CSS 完全碰不到，做不出动画和质感 —— 想要就得自己画（v0.8.1 起项目下拉是自绘的）。
- **多行备注里为什么回车是换行**：多行框里回车即提交，等于**永远写不出一段分段的备注**。所以 `Enter` 换行、`Ctrl+Enter`（Mac 是 `Cmd+Enter`）才保存。
- **弹窗为什么是直角**：窗口外形由浏览器绘制，扩展侧改不了（官方 issue 状态 `Won't fix`）。被当标签页打开时才有圆角。
- **为什么删掉「恢复归档 N」**：全量恢复是把看板一次翻乱的动作，已彻底删除，**不要再加回来** —— 详见第五节。
- **为什么要有第二套编辑界面（编辑抽屉）**：就地编辑是长在列里的，列宽只有约 **138px**，字段一多就挤成竖着一条 —— 「改长内容」这件事需要的是**宽度**，不是更多控件。所以抽屉负责「认真改一条」，就地编辑继续负责「顺手改个标题」，**两条路都留着，不是替换关系**。
- **自然语言输入的退路**：设置页「填写」里可以关，关掉之后就是**原样记一笔**，一整句都当标题。任何「聪明」的输入改造都必须留退路 —— 解析本质是猜，在某些写法上必然猜错。
- **`#` 为什么只认已有的项目名**：所以「**修复 bug #12**」不会被当成项目 —— 这是自然语言输入最常见的一类误伤，靠「必须命中已有项目」从根上避免。
- **「浮到桌面」为什么会是「两下」**：官方要求「开画中画窗口」必须由**真实点击**触发，而新开出来的窗口是全新文档、没有点击可言。宿主页先无声地试一次，浏览器放行就一步到位、不放行就自己变成一个按钮让你点 —— 这一步**绕不过去**，扩展侧没有任何办法替你点。（v0.14.0 已经把入口删了，这里留着是为了以后别再掉同一个坑。）
- **网页上那颗球为什么走「只装扩展」这条路**：官方明文，只要设了 `default_popup`，`action.onClicked` 就不会触发 —— 「点图标直接出球」在浏览器层面做不到，零点击只能靠注入网页。**代价是它只活在网页上**；想要「任何界面抬头都在」得装桌面那颗（**可选**，两条路读同一份数据）。这颗球**不是浏览器插件里的一个浮窗** —— 它没有任何窗口，就是网页里的一个元素；而桌面那颗之所以必须是**独立的桌面程序**，是因为透明 / 无边框 / 置顶 / 不进任务栏全在操作系统窗口层，扩展 API 够不着。
- **说明文字为什么钉进「!」而不是铺在界面上**（v0.16.1）：v0.15.0 把介绍清零之后，「**必须让用户知道**」的那部分一度没地方放 —— 铺回界面上就又是一屏小字，用户不读还嫌乱。所以定了条规矩：功能块**右上角**钉一个**半透明的小感叹号**，鼠标移上去（或 Tab 聚焦）才展开，而且展开的**必须是键值行，不能是散文**（散文换个地方摆还是散文）。界面上只留两样东西——**状态**（现在能不能用）和**动作指引**（差一步该干什么）；原因、边界、代价全进卡片。★ 实现上是纯 CSS（`:hover` + `:focus-within`）：设置页 CSP 禁内联脚本，而 `.q` 带 `tabindex="0"` 既让键盘可达，也让**无头验收**能展开卡片 —— `:hover` 在无头里点不出来。
- **设置页为什么从「六块铺一页」改成「左导航切页」**（v0.17.0）：功能一多，设置页就成了一条**长走廊** —— 想看飞书得先滚过项目、填写、球三屏。改成切页之后一次只有一块，滚动距离归零。做法上是**只翻 `hidden`、不重建 DOM**：表单里敲了一半的值、已经绑好的监听器、脚本里存的 element 引用全都原样有效（判据是「5 块都还在 DOM 里」，不是「只看得见一块」—— 少了这一条，改成重建 DOM 也能骗过测试）。`hash` 仍是 `#s-xxx`，刷新 / 前进后退 / 转发链接都能复现同一页；**认不出的锚点落回第一块，绝不留一屏空白**。★ 「数据」那处折叠（`dataToggle`）随切页一起删了 —— 点「数据」本身就是在说「我要看它」，再让用户多点一次是白加一层。★ 「填写」**没有**新增导航项，而是做成「项目」页的页内子标签：它和项目列表同源（都在决定「任务长什么样」），做成平级会让人以为它们无关。子标签是**重置**不是「记住」—— 点「项目」就该看到项目列表，唯一例外是老书签 `#s-input`（「填写」当年的锚点）：落到「项目」页并自动选中「记一笔」。★ 右侧那块小标题栏（rail）也收掉了 —— 左边导航已经高亮着「你在哪一页」，右边再写一遍同名标题是重复，还白占 200px 版面；状态统计挪到本页顶部一行。★ 收掉 rail 之后**看图看出一个真问题**：AI 页顶上只剩一句「走云端」，孤零零挂着读起来是个**断句** —— 它原来头顶有「AI 能力」四个字兜着，所以一个谓词也成立。于是给这行加回**主语**（`AI 能力 · 走云端`）。**这不是把 rail 搬回来**：rail 是「标题 + 状态」两行、竖着排、还占 200px 版面，那是重复；这里加的是**谓词的主语**，跟项目页那行「共 N 条任务…」里的「任务」同一个角色。项目页那行本来就自明，**没动**。
- **看板为什么单独开一页、而不是塞进「数据」**（v0.18.0）：它和「数据」不是一类东西 —— 「数据」是**出入口**（导出 / 导入 / 归档 / 清空），看板是**读数的地方**。摆在一起会让人以为「导出」和「看趋势」是同一层的事。做法上它是 `#s-board` 的第六块 section，仍然遵守 v0.17.0 那条「只翻 `hidden`、不重建 DOM」；数字全部由 `Board.compute(tasks, projs)` 算出来 —— 那是个**纯函数**，不碰 DOM、不碰 storage，测试可以直接喂数组进去验口径。★ 口径必须跟设置页顶部那行统计**逐字一致**（「在手 / 未完成」都排掉归档）：同一个数在两个地方长得不一样，比不显示更糟。★ 「平均完成周期」在一条都没完成时是 **`–`（不知道）不是 `0`（真没有）** —— 这是老规矩，看板也不例外。
- **主题为什么用 `localStorage` 而不是 `chrome.storage`**（v0.18.0）：`chrome.storage` **只有异步 API**，读它必然在首帧之后 → 先画一帧白、再刷成暗的（闪白）。`localStorage` 是同步的，`theme.js` 因此能在 `<head>` 里**阻塞式**跑完并把 `data-theme` 挂到 `<html>` 上 —— 首帧就是对的颜色。代价是它不同步到别的设备，而主题本来就该跟着这台设备走。★ 「没表态过」和「表态过亮色」是两回事：`taskboard.theme` 只认 `light` / `dark` 两个合法值，垃圾值一律当「没设过」→ 回落系统设置；用户一旦点过开关，系统再变也不跟了。
- **AI 大模型为什么从「三个输入框」变成「一个列表」**（v0.18.0）：真用起来的人不止一个供应商 —— 便宜的跑日常、贵的跑难题，还要能随时换。固定的 base/model/key 逼人每次去手改三个框，而且改回去就丢了上一套。★ 「本机模型」**不进这个列表**：那是浏览器的能力，不是一条配置，塞进去会让「删掉本机模型」变成一件荒谬的操作。所以上面「在哪跑」那块留着（选走哪条路），这个列表只管云端那一路。★ 列表是**渲染出来**的（骨架里没有半行静态行）：每行的选中态和编辑 / 删除按钮都要跟着数据走，写死一行就是欠一笔将来的同步债。
- **输入框旁边那个下拉，为什么第二次点要收起**（v0.18.0）：原来是「点开 → 点别处关」，于是同一个按钮点两下会变成「开着 → 还是开着」，读起来像坏了。改成**开关**：点它自己不关（那是切换），点外面才关（那是失焦）。两件事必须分开记状态 —— 只靠「点外面关」这一条，按钮自己就永远关不掉。
- **浮层定位为什么不能用 `getBoundingClientRect()` 量自己的盒子**（v0.19.0 验收时量出来的）：`.selpop`（项目下拉）**一创建就带着入场动画** `transform:scaleY(.86)`，而定位是在**动画还没开始**那一刻算的 —— `rect` 量到的是缩水版：上限 320px 量成 **275px**（少 45px / 14%）。后果是「上面放不放得下」判错：真机里那个锚点在 `top=295`，上面最多塞得下 275，代码却按「275 放得下」把面板翻了上去，最后**压住自己的触发按钮**。改用 `offsetWidth` / `offsetHeight` —— 布局尺寸，与 `transform` 无关。★ 更该记的是**它为什么一直没被断言抓到**：验收脚本量的是同一个 `.selpop`，用的也是同一把错尺子（也是 275），于是**代码和断言共用一把尺子 → 自洽地假绿**。所以验收脚本量 `rect` 之前必须**先杀过渡**（`transition/transform` 置 `none`），并且要有一条「量到的必须是布局盒（`height == offsetHeight`）」的哨兵专门盯**尺子本身**。★ 同一条规则顺手统一到了 `.qpop`（快捷改期那个浮层）：它眼下没有入场动画、两种写法量出来一样，但**同一条规则不该有两套写法** —— 哪天给它加入场动画，那行就是下一个静默失效。
- **几何断言为什么不能钉在「某个具体按钮」上**（v0.18.0 埋的雷，v0.19.0 才炸出来）：顶栏那条「最后一个按钮贴右沿」原先把「最后一个」写死成 `#btnData`。v0.18.0 在它右边又加了**主题开关**，断言的量法没跟着走 —— 于是它量到的是「52px 开关 + 8px 间距 = 60px 的空档」，**从那天起一直是红的**，还两次被当成「别的变异打红的行」（所以：**基线不绿就别跑变异验证** —— 一条常年红的既有断言会污染判据）。改成量「最后一个**可见**子元素」之后，以后再加控件这条断言自己跟着走。★ 顺带补了两条：顶栏最右那个确实是 `themeSw`、以及主题开关真的占位可见（0 宽或被隐藏就等于没这功能）—— 它从 v0.18.0 加进来起一直没有真机断言。

## 一、在 Chrome / Edge 里装

1. 拿到 `task-board-extension-v0.24.0.zip`，**解压到一个固定位置**。建议目录名**不带版本号**，比如 `D:\task-board-extension\` —— 这样以后升级只要覆盖里面的文件就行。
   ⚠️ 别放在「下载」或桌面然后删掉 —— 扩展是「加载已解压的目录」，文件夹没了扩展就废了。
   ⚠️ 如果之前装过旧版，**先在扩展管理页把旧的那个移除掉再装**（只针对这次从旧版迁过来；装好 v0.6.3 之后就不用再移除了，见下面「以后怎么升级」）。
2. 打开浏览器，地址栏输入 `chrome://extensions` 回车。
3. 打开右上角的「**开发者模式**」开关。
4. 点左上角「**加载已解压的扩展程序**」，选中第 1 步解压出来的文件夹（选到有 `manifest.json` 的那一层）。
5. 装好后点工具栏的拼图图标 🧩，找到「任务台」，点右边的图钉把它**固定到工具栏**，以后点一下就能开。

Chrome 127 或更高版本可以直接用快捷键唤起弹窗；更低版本快捷键会自动改成「在新标签页里打开」，功能一样。

### ★ 以后怎么升级（数据不会丢）

**一句话：别删旧的，把 14 个文件 + 一个 `icons` 文件夹覆盖进去，回扩展管理页点一下「刷新」。**

```
覆盖文件  ──▶  点刷新  ──▶  重开弹窗
```

这三步全程只动代码，**任务、项目、挂起项、App ID / App Secret / Base token 一个都不会变**。

#### 动手之前，先花 30 秒保个命

打开设置页 →「数据」→ 点「**导出 JSON**」，存到桌面。万一出任何意外，「导入 JSON」能原样回来。
（这一步纯属保险，正常情况下用不上。第一次升级建议做。）

#### 第 1 步 · 找到你现在用的是哪个文件夹

1. 地址栏输入 `chrome://extensions` 回车。
2. 右上角「**开发者模式**」如果是灰的，先打开。
3. 找到「任务台」那张卡片。**卡片上会写着这个扩展的文件夹路径**（只有开发者模式下才显示），点那行就能直接在资源管理器里打开。
4. 实在找不到路径就别猜了，回想一下当初装的时候解压到哪了 —— 常见的就是桌面、下载、或者 `D:\task-board-extension\`。
   > 万一真的找不到：因为 v0.6.3 起 manifest 里有固定的 `key`，扩展 ID 跟目录路径已经解耦。所以**先在旧版里导出一份 JSON**，然后把新包解压到任意新目录、加载，再用「导入 JSON」把任务导回来即可。

#### 第 2 步 · 把新包解压出来

1. 右键 `task-board-extension-v0.24.0.zip` →「**全部解压缩**」。
2. 解压完打开，看到的应该是 **15 个文件平铺 + 1 个 `icons` 文件夹**：

   ```
   manifest.json   background.js   popup.html   popup.js
   manage.html     manage.js       feishu.js    sync.js     ai.js       ball.js
   host.html       host.js         README.md
   ballwan.html    ballpage.js
   icons/          ← 里面 4 张图标（16 / 32 / 48 / 128），v0.7.1 起有
   ```

   `host.html` / `host.js` 是 v0.10.0 的「浮到桌面」宿主小窗（**v0.14.0 起已经没有入口了** —— 弹窗里那个按钮被删掉，它就是要「点两次」的那个东西；文件先留着，没人调用就是死代码）；`ai.js` 是 v0.16.0 的 **AI 抽象层**（内置模型 / 云端两套实现收在一个文件里，弹窗和设置页共用）；`ball.js` 是 v0.11.0 的球桥（跟桌面那颗球对话用的）；`ballwan.html` 是**预览壳**（调球的样式时不用装扩展、不用开网页就能看），`ballpage.js` 是**注入到每个网页上的那颗球**（v0.14.0，content script，样式和逻辑都收在这一个文件里）。**它们谁都别删** —— 少了 `ball.js` 是桌面程序那颗球连不上，少了 `ballpage.js` 是网页上那颗球整个消失，**两种都不报错**。

   > 从 v0.13.0 升上来的话：**交互被砍到一层**（点球直接弹输入框，滑杆和迷你列表都删了），弹窗顶栏那个「浮到桌面」按钮也没了；`ballwan.css` / `ballwan.js` 这两件仍然不需要。**重载扩展之后，记得刷新一下已经开着的标签页**，不然网页上不会长出球。

3. ⚠️ **如果你看到的是一层文件夹、点进去才是这些文件** —— 别把那个文件夹整个拷过去，会变成「旧目录 / 新文件夹 / manifest.json」这种套娃，扩展就加载不出来了。要用的永远是**里面这一层的内容**。
   `icons` 是**唯一一个应该出现的子文件夹**（放图标用的），其余文件都平铺。

#### 第 3 步 · 覆盖进原来的目录

1. 打开第 1 步找到的那个目录。
2. 把解压出来的 **15 个文件 + `icons` 文件夹全部选中**，复制粘贴进去。
3. 弹出「目标已包含同名文件」→ 选「**替换目标中的文件**」。
4. 覆盖完对一眼：目录里还是 14 个文件 + `icons` 文件夹（里面 4 张图），**别出现两个 `manifest.json`**。
   ⚠️ 覆盖之前那个目录里**没有** `icons` 文件夹，所以这次会多出一个 —— 这是对的，别删。
5. 目录路径**不要变**，也别新建一个带版本号的文件夹搬进去。

#### 第 4 步 · 回扩展管理页点「刷新」

这是整个升级真正的开关。**不点刷新，新文件只是在硬盘上躺着，浏览器跑的还是老代码。**

- 位置：`chrome://extensions` → 任务台卡片**右下角的圆形箭头按钮**（是卡片上那个，不是点进「详情」里面的）。
- 点完，卡片上的版本号会变成 `0.24.0`。
- 如果卡片冒出红色的「**错误**」按钮 —— 停手，别用，把报错原文发我。

#### 第 5 步 · 关掉旧的弹窗 / 设置页，重新打开

新代码装上了，但**已经打开着的界面还跑着老代码**，这一步最容易漏：

- **弹窗**：如果现在开着，先点旁边空白处关掉，再重新点工具栏图标。
- **设置页**：如果你是把它当**标签页**开着的，那个标签页里还是老的一套 —— 关掉重开，或者直接按 F5。

漏了这一步的典型表现就是「升级了，但界面看起来什么都没变」。

#### 第 6 步 · 验四件事

| 验什么 | 在哪看 | 应该是什么样 |
| --- | --- | --- |
| 版本号变了 | `chrome://extensions` 任务台卡片 | `0.7.1` |
| 新代码真的在跑 | 设置页 →「数据」卡片 | 多出一行「升级时自动存了一份 v0.6.5 的数据（时间，共 N 条任务）」 |
| 数据还在 | 弹窗里的任务、设置页里的项目 | 跟升级前一模一样 |
| 凭据还在 | 设置页 →「飞书同步」→「底表」那一行 | 表名 + 条数正常显示，没让你重填任何东西 |

#### 第 7 步 · 确认没问题了，再处理旧备份

设置页「数据」里那行备份，点「**丢弃**」清掉即可。**确认新版好用了再点，别提前丢。**

#### 升级会保留什么

| 保留 | 会变 |
| --- | --- |
| 全部任务、项目、挂起项 | 只有那 9 个代码文件 + `icons` 里的 4 张图 |
| App ID / App Secret / Base token / 表 ID | —— |
| 飞书同步映射、冲突日志、界面设置 | —— |

#### 翻车对照表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 报「清单文件缺失或不可读」 | 解压多套了一层文件夹，或粘贴进去的是文件夹本身 | 只把那一层的内容放进有 `manifest.json` 的目录（`icons` 文件夹要一起带过去） |
| 界面完全没变化 | 弹窗没关、或设置页标签页没重开 | 重做第 5 步 |
| 版本号还是旧的 | 没点卡片上的刷新，或复制时漏了文件 | 重做第 3、4 步 |
| 任务全没了 | 点的是「**移除**」而不是「刷新」 | 用动手前导出的那份 JSON 导入回来 |

**为什么以前那样做会丢数据？** 因为 v0.6.2 及更早的版本没有 `key`，扩展 ID 是**由解压目录的路径推导出来的**。你把新包解压到一个新目录再「加载已解压的扩展程序」，浏览器会认为这是一个**全新的扩展** —— 新 ID、新存储，原来的配置和数据当然接不上。所以才会出现「每次装新版都要重填 App Secret」。

**v0.6.3 起不会再有这个问题**：manifest 里加了一个固定的 `key`，扩展 ID 被钉死成

```
bjellcogampafiiolhaiccmeakighadj
```

从此**跟文件夹路径彻底解耦** —— 你把文件夹挪到别的盘、改个名字、甚至删了重新解压到全新的目录，只要装的是同一个包，扩展 ID 都是这个，数据照样在。

> ⚠️ **这次从旧版升到 v0.6.3 会有一次性的 ID 变化**（旧版没有 key），需要一次性搬迁：
> 1. 旧版设置页 →「导出 JSON」存好
> 2. 旧版设置页记下飞书的 App ID / App Secret / Base token / 表 ID
> 3. 扩展管理页移除旧版 → 装 v0.6.3
> 4. 新版设置页 →「导入 JSON」把任务导回来 → 重填飞书那四项
>
> **这是最后一次。** 之后升级就是覆盖 + 刷新，两秒钟的事。
> 数据不多的话，直接装 v0.6.3 从零开始也行 —— 飞书那边本来就没数据。

**另外两道保险，防止任何意外：**

- **升级前自动备份**：v0.6.3 起，只要版本号变了，扩展会自动把上一版的数据存一份。设置页「数据」卡片里会显示「升级时自动存了一份 vX.X.X 的数据（时间，共 N 条任务）」，旁边有「**恢复这份备份**」按钮，一键退回。确认新版没问题后点「丢弃」即可。
- **手动导出**：设置页随时能「导出 JSON」，这是最彻底的一份保险（建议存到网盘或发给自己）。

## 二、在 Tabbit 浏览器里装

**结论：能装，直接用同一个 zip，步骤和 Chrome 完全一样。**

Tabbit 是 Chromium 内核的浏览器，实测结论如下：

| 检查项 | 实测结果 | 怎么验的 |
| --- | --- | --- |
| 内核版本 | **Chromium 151.0.7922.138** | 二进制定位 + 浏览器自报版本，两处独立确认 |
| 能不能加载 MV3 扩展 | ✅ 能 | 用 `--load-extension` 实测，本扩展的 background service worker 成功注册并运行 |
| 有没有扩展管理页 | ✅ 完整保留 | `chrome://extensions` 可打开；内核里含 `loadUnpacked`、`devMode`、`developer-mode` 等界面入口 |
| 开发者模式 / 加载已解压 | ✅ 有 | 内核含「开发者模式」「打包扩展程序」等完整文案 |
| 扩展基础设施 | ✅ 完整 | 用户目录下有 `Extension State`、`Local Extension Settings`、`extensions_crx_cache`、`external_extensions.json` |

安装步骤：完全照上面第一节走一遍，把 `chrome://extensions` 换成 Tabbit 的地址栏即可。Tabbit 的工具栏可能不显示扩展图标（各家自研 UI 不一样），这种情况下有两个入口：

- 按 `Ctrl+Shift+L` 打开（Tabbit 151 支持 `action.openPopup`，会以弹窗形式出现）
- 如果快捷键的弹窗被浏览器拦了，会自动退化成「在新标签页里打开任务台」，功能不受影响

> 说明：完整的内核版本是 151，我们只用到了 Chromium 88~127 时代就稳定下来的 API（`storage` / `action` / `contextMenus` / `commands`），因此在 Tabbit 上不存在 API 缺口。
> 唯一没能在本机实测的是「弹窗 UI 在 Tabbit 窗口里的观感」—— 因为这台机器的沙箱环境起不了 Tabbit 的 GPU 子进程。请按下面第八节自查一次。

## 三、怎么用

| 想干嘛 | 怎么做 |
| --- | --- |
| 记一笔 | 点右上角图标，弹窗里直接打字，回车即建。默认落在「待办」 |
| 随手记 | 任何网页按 `Ctrl+Shift+L` 唤起；或在网页上右键 →「把当前页存到任务台」 |
| 改状态 | 把卡片拖进别的列。拖进「已完成」会自动记下完成时间 |
| **挂起** | 把卡片拖到看板**最右边那条紫边**上。挂起的任务会从主视野退出去，只留一个数字 |
| **取消挂起** | 点那条紫边，浮层里点一下卡片就放回待办 |
| 改内容 | 点一下卡片，**标题、备注、日期、项目、优先级**都能直接改；**回车保存，或者点屏幕上任何别的地方也保存**。点回卡片里面**不会**被当成保存，可以放心填。**备注是多行框、会跟着内容长高**：里面回车是**换行**，保存用 `Ctrl+Enter`（Mac 是 `Cmd+Enter`） |
| **大编辑（改长内容）** | 三个入口：卡片右下角的展开图标（鼠标移上去才出现）／ 就地编辑卡底部的「展开到大编辑」／ 键盘 `e`。整幅宽度，**改了就自动存**，头部会显示「已保存」；删掉标题不会存成空的 |
| **打字就能带日期/项目** | 在「记一笔」里写「明天交周报 #工作 !高」，回车即建。输入框下面那条预览会实时告诉你它认出了什么。不想要 → 设置页「填写」关掉 |
| **搜任务** | 顶栏点「搜索」，或按 `/`（`Ctrl+F` 也行）。匹配标题和备注、命中处会高亮；**不受当前视图限制**（在「今天」里也搜得到下周的）。`Esc` 退出 |
| **快速改期** | 鼠标移到卡片上，点**右下角的日历小图标** → 今天 / 明天 / 下周 / 清除日期，点一下生效。挂起卡和「按项目」视图里，直接点那行**日期文字**也行 |
| **纯键盘操作** | `↑` `↓`（或 `j` `k`）在卡片间移动，`Enter` 打开这张卡，`1` / `2` / `3` 改成 待办 / 进行中 / 已完成，`d` 改期，`e` 打开大编辑，`n` 跳到「记一笔」，`Esc` 收起。**只在没在输入的时候生效** |
| **归档已完成** | 底栏「归档已完成」把已完成列收起来。**不是清空**，数据一条不删；取回方式是底栏的「归档 N」——点开是一份只读清单，在里面**逐条**挑着拿回来（取回也带撤销），设置页「数据」区会显示「已归档 N 条」并告诉你去哪儿取 |
| **设优先级** | 点开卡片 →「优先级」→ 点「高 / 中 / 普通」。**不设也行**，每列最上面三件会自动高亮 |
| 删任务 | 鼠标移到卡片上，点右上角的 `×`。点完提示条右边有「**撤销**」，会把它**放回原来的位置**（只保留最近一次） |
| 换视角 | 顶部切「今天 / 按日期 / 按项目」 |
| **看这周干了多少** | 底栏底部的「**本周完成 N 件**」。周一起算，已归档的也算；**一件没有的时候不显示** |
| 改项目、导出导入 | 点弹窗右上角「数据」，会打开设置页 |
| **网页上的球（零安装）** | 打开任意网页就在（贴屏幕右边缘、垂直居中、平时半透明）。**点一下球 = 记一笔**，打完回车；按住能拖、松手吸附到最近的边（球旁边不挂任何按钮；进设置走扩展图标 → 弹窗）。**重载扩展后要刷新（F5）一次才会出现** |

三个视图的区别：

- **今天**（默认）：只显示今天及以前还没做完的任务（过期的会标橙，必须看得见），外加今天完成的。这个视图是为了「现在该干嘛」，不是仓库。**挂起的不算进来。**
- **按日期**：全部任务按日期从早到晚排。
- **按项目**：全部任务按项目分组排。

图标上的数字是未完成任务数，**不含挂起**——挂起的意思是「这事先不占我的心力」，再把它数进去等于白挂。

待办列超过 7 项时数字会变橙色 —— 认知科学上，手头选项超过 7 个，决策质量会明显下滑，提醒你该收一收了。

Windows 快捷键是 `Ctrl+Shift+L`，Mac 是 `Command+Shift+L`。

### 弹窗里的单键（v0.9.0 起，v0.9.1 加了 `e`）

弹窗打开着的时候，下面这些键**不用加任何修饰键**，直接按就行。**下面这张表就是速查** —— v0.15.0 起弹窗里不再有 `?` 浮层，界面里不摆说明。

| 键 | 干什么 |
| --- | --- |
| `↑` `↓` 或 `k` `j` | 在卡片之间上下移动（会有一圈光标描边） |
| `Enter` | 打开光标停的那张卡（在备注框里，`Enter` 是**换行**） |
| `1` / `2` / `3` | 把光标停的那张卡改成 待办 / 进行中 / 已完成 |
| `d` | 给光标停的那张卡快速改期 |
| `e` | 打开光标停的那张卡的**大编辑抽屉**（改长内容用这个；就地编辑那个小框留给「顺手改个标题」） |
| `n` | 光标跳到顶部「记一笔」输入框 |
| `Esc` | 收起当前浮层（后开先收）、退出搜索 |
| `/` 或 `Ctrl+F` | 进入搜索 |

有两条规矩值得说明：

- **只在没在输入的时候生效。** 你正在标题框、备注框、搜索框里打字，上面这些键一个都不会被抢走（不然在搜索框里敲 `n` 会突然跳出新建）。
- **只认单键，不认 `Ctrl` / `Cmd` 组合。** 组合键留给浏览器和系统自己 —— 抢掉 `Ctrl+W` 这种事是不能干的。

按 `1` `2` `3` 把任务改成「已完成」，**和用鼠标拖过去得到的反馈完全一样**：有落位动画、也有「撤销」。这两条路走的是同一段代码，不会出现「拖过去有动画、按键盘悄无声息」这种最难查的不一致。

## 四、挂起是什么、为什么这么设计

**挂起 = 「暂时不做，但也没放弃」。** 它和「删除」和「已完成」都不一样，是第三种收场方式。

看板上只给了它一条 36px 的窄边，不是一整个列。这是故意的：

- 挂起的全部意义就是**让人别惦记它**。给它一个和待办、进行中平起平坐的位子，等于没挂起。
- 所以它缩成一条边，只露一个数字。数字出现说明你有事搁着，但不占你今天的注意力。
- 想找回来的时候点一下就够了，不会丢。

一件事该挂起而不是删掉的典型场景：等对方回复、等一个前置条件、这周没排上但下周要做、想清楚了再动。

### 状态色

看板上每张卡片的颜色就是它的状态。这套用色不是随手挑的，沿用了成熟看板工具的通行惯例：

| 状态 | 颜色 | 为什么是这个色 |
| --- | --- | --- |
| 待办 | 灰 | 「未承诺」要**视觉后退**——没人会为灰色的东西焦虑 |
| 进行中 | 蓝 | 活跃态。蓝色传达「在动」，但不制造警报 |
| 已完成 | 绿 | 通行色，而且要**做得最不抢眼**——完成的事不该再争夺注意力 |
| 挂起 | 紫 | **等待态，不是工作态**，必须和活跃的蓝色明确区分开 |

两条用色铁律，改配色时请一并遵守：

1. **一种颜色只能有一个含义。** 比如橙已经用来表示「已过期」了，就不能再拿它表示挂起，否则两个意思会互相干扰。
2. **不要给每张卡都上饱和色。** 颜色是最快的信号，也是最容易被浪费的视觉资源——全都染色等于全都没染。

所以实现上：列头是一层淡淡的状态色底（13%），卡片是一层更淡的填充（10%）加一圈状态色描边（24%），已完成和挂起的卡片再降透明度。四列并排看到的是**淡淡的色温差异**，不是四块彩色便利贴——这样毛玻璃的通透感才保得住。

### 优先级亮度（v0.7.0 新增）

卡片标题的深浅，就是它的优先级。**只做三档，不做四档** —— 白底上正文的最低对比度是 4.5:1，这是条硬下限；在这条线之上再塞四档，每档只差约 1.3 倍，肉眼根本分不出来。三档每档能拉开约两倍，才看得清。

档位是**双轨**的，你一个设置都不用做：

- **位置驱动**：每列最上面那三件，自动就是最黑的。新用户打开就能用，不需要先理解「优先级」这个概念。
- **手动覆盖**：点开卡片，在「优先级」那一行点「高 / 中 / 普通」，这条就按你设的走 —— 哪怕它排在列尾。

两条规则不会打架：手动设过的只影响它自己那一条。

几个刻意的决定，改样式时请一并遵守：

1. **不只用深浅**。高档同时**加粗**。只靠颜色区分，色盲、低亮度屏、强光下会全部失效 —— WCAG 1.4.1 明确禁止把颜色当作唯一的信息通道。
2. **不整行变淡**。只把标题文字调浅，日期、项目色点、链接全都保持原样。整行降透明度看起来像「这个按钮坏了」，还会把项目色一起洗掉。
3. **已完成列不叠优先级**。完成的事靠后退表达就够了，再叠一层深浅属于双重编码，两套「次要」会互相削弱。

排序规则是「**显式序位 → 优先级 → 视图原本的规则**」。如果你在飞书表里给某一行填了「排序序位」，那个数最小的排最前 —— 这是唯一一个能表达「我就要它排第一」的手动信号。

### 完成时的反馈（v0.7.1 修好，v0.8.0 瘦身）

把卡片拖进「已完成」，它会走一套大约半秒的动作：落位回弹一下 → 一圈绿环扩散 → 勾一笔描出来 → 散出几点小粒子 → 退淡。

> **v0.8.0：「标题划掉」那条去掉了。** 就是那条从左往右扫过去的横线。它的信息已经被「落位回弹 + 绿环 + 勾」表达完了，多一条线只是热闹。代码里留了注释说明**不要再加回去**。

> **v0.7.0 写了这套动画，但实际看不到。** 原因是拖完要写一次本地存储，而写存储会让弹窗再重绘一遍 —— 刚贴上动画的那张卡立刻被换掉，动画跟着一起消失。现在用一个 900ms 的「播报窗口」兜住：窗口期内不管重绘几次，动画都会重新贴到新的那张卡上。另外原来「已完成」列的卡片统一压了 72% 透明度，等于压着播动画，现在刚完成那张会临时恢复满不透明。

这不是装饰。**「已完成」是唯一一个不可逆的收场**（挂起能捞回来，删除是你主动点的），所以它需要一个明确的收尾信号，让你确认这一下真的生效了。拖完毫无反应的话，人会怀疑是不是没拖准。

系统开了「**减少动态效果**」（`prefers-reduced-motion`）时，会换成不动的呈现 —— 勾直接出现，信息一点没少，只是不动。

## 五、数据在哪、怎么带走

数据存在浏览器本地（`chrome.storage.local`），也就是你自己这台电脑里。**Chrome 和 Tabbit 的数据是各自独立的**，互不相通。

- 弹窗右上角「数据」→ 打开设置页
- **导出 JSON**：完整备份（含项目配置），可以再导入回来
- **导出 Markdown**：给人看 / 贴进笔记软件（挂起单独成组，排在已完成前面）
- **导入 JSON**：按 id 合并，同 id 跳过，**不会覆盖现有任务**

想让 Chrome 和 Tabbit 两边数据一致：在一侧「导出 JSON」，到另一侧「导入 JSON」。换电脑、重装浏览器、清理浏览器数据之前，先导出备份。

**「归档已完成」（v0.8.0 起，v0.8.1 改了取回方式）和「清空」是两回事。** 归档只在本地给那些任务打一个标记，**记录一条都不删** —— 导出 JSON 依然能看到它们，飞书那边也照旧。它只是让已完成列不再堆着历史。

**怎么取回（v0.8.1）**：底栏点「归档 N」，右侧滑出一份清单，里面就是全部归档任务，每条旁边一个「恢复」。**想拿回哪条就拿回哪条，其余一条不动**（取回也带撤销）。

> **为什么把「恢复归档 N」删掉了。** 它一次把 N 条**全部**倒回看板 —— 你原话是「点击归档后又恢复归档，这样来回操作会把我已有的信息打乱掉」。全量恢复确实是那个把看板一次翻乱的动作；**逐条**取回才让人能挑着要。所以那个按钮**已彻底删除，不要再加回来**（代码里留了注释）。
> **设置页的「数据」区只报个数 + 指路**：有归档时多一行「已归档 N 条」和一句「要取回某一条，在弹窗底栏点『归档 N』」；一条归档都没有时整块不显示，不占版面。
> 为什么不给「清空」：清空是不可逆的，误点一次就没了；归档是可逆的，收益一样而风险为零。所以设置页的「数据」区里**没有任何清空按钮**，也**没有任何会改数据的按钮** —— 只有导出、导入。

> v0.6.0 起，如果接了飞书多维表格（下一节），它也能承担「永久保存 + 跨端可编辑」这件事——而且比手工导出导入省事。

## 六、接飞书多维表格（可选）

**不接完全不影响用。** 接上之后多两个能力：数据永久落在飞书表里（浏览器数据被清掉也不怕），以及可以**直接在飞书那边改**（在手机上、在网页上，改完扩展会认）。

### 为什么是「本地优先 + 飞书镜像」，不是飞书当主库

想过让飞书表当实时主库，放弃了，三个原因：

| 问题 | 后果 |
| --- | --- |
| 每次读写要等飞书往返 200~500ms | 拖一下卡片卡半秒，忍不了 |
| 飞书同一张表**不支持并发写**（报 `1254291 Write conflict`） | 快速连拖几个任务就会互相撞，得排队 |
| 断网 = 废掉 | 本地磁盘开着也能用，飞书做不到 |

所以架构是：**本地照旧是第一现场，飞书是镜像。** 你在这边怎么用都不受影响，飞书那份跟着走。

### 怎么接线

两套路子。**新同事走路线 A**（扩展把表建好）；自己已经有表的走路线 B。两条最后都是回到设置页填那四个框。

#### 路线 A：让扩展帮你建表

**先在开放平台准备应用（3 步）：**

1. **建一个自建应用**：飞书开放平台「创建企业自建应用」→ 在 **「凭证与基础信息」** 页拿到 `App ID`（`cli_` 开头）和 `App Secret`。
2. **开通权限**：进 **「权限管理」**，搜 `bitable`，开通 **`bitable:app`**（「查看、评论、编辑和管理多维表格」）。

   ⚠️ **别只开 `bitable:app:readonly`**。只读的话「读数据表」能过，但「写记录」那几行会一路失败 —— 报错信息长得跟没开权限一样，很容易看错。
3. **创建版本并发布**：进 **「版本管理与发布」** → 创建版本 → 申请发布（你是管理员就直接通过）。
   ⚠️ **这步最容易漏**：权限开了但不发布版本，等于没开，照样报 403。飞书不会提示你少了这一步。

**再回扩展设置页（2 步）：**

4. 填 **App ID** 和 **App Secret**。**就这两项，没有别的要填。**
5. 点 **「创建多维表格」**。扩展会连着做完：建一张新表 → 把 11 个字段按名字和类型摆好 → 清掉平台自带的那张空表 → 把表设成「组织内拿到链接的人可编辑」→ 把 Base token 和数据表 ID 自动填好并开始同步。

做完去飞书「云文档 → **共享给我的**」就能找到这张表，打开就能直接改，改动会回流到扩展。

> **这张表的所有权归「应用」，不归你。** 飞书官方明文规定：应用以**应用身份**创建的多维表格，所有权属于应用，用户默认只有阅读权限；应用以**用户身份**创建的才归用户。
>
> 这条规定对扩展**没有任何影响** —— 应用自己就是所有者，读写这张表一路畅通，连「把应用加进表」（协作设置 → 添加文档应用）那一步都不用做。
>
> 它只影响一件事：**你打开飞书网页时能不能手动改**。所以第 5 步里扩展会顺手把这张表的**链接分享设成「组织内拿到链接的人可编辑」** —— 组织维度，不需要知道你是谁，所以也就**不需要填邮箱**。
>
> 这一步是**可选**的：万一没设上（比如应用缺云文档类权限、或企业策略不允许），**表照样建好了、同步照样跑**，只是你在飞书网页里打开它只能看不能改。报告里会把这一档标成「**可选**」，不会算成失败。

#### 路线 B：手动接一张已有的表

1. **准备一张表**，字段名必须和下面**逐字一样**（差一个空格都不行，飞书是按名字找字段的）：

   | 字段名 | 类型 | 用途 |
   | --- | --- | --- |
   | `任务` | 文本 | 标题 |
   | `状态` | 单选 | 待办 / 进行中 / 已完成 / 挂起 |
   | `项目` | 单选 | 你的项目名 |
   | `日期` | 日期 | 排期 |
   | `备注` | 文本 | 备注 |
   | `链接` | 超链接 | 存网页时带的 URL |
   | `本地ID` | 文本 | **同步的钥匙，别手改这个字段** |
   | `创建时间` | 日期 | |
   | `完成时间` | 日期 | |

2. **拿 Base token 与 Table ID**：打开那张表，地址栏 `.../base/` 后面那串就是 Base token；再点开某个数据表标签，`table=` 后面那串就是 Table ID（形如 `tblXXXXXX`）。
   💡 **偷懒办法**：把**整条地址**粘进设置页那个「或者已经有表了，就把整条链接粘进来」，扩展会自己拆出这两个值。如果链接里没带 `table=`（从表格首页复制出来的就长这样），它还会去查这张表下有哪些数据表 —— 只有一个就自动填上。
3. **建应用 / 开权限 / 发布**：同路线 A 的第 1~3 步。**这一路不需要开通「添加云文档协作者」权限** —— 那是加协作者才要的，跟第 4 步的「添加文档应用」不是一回事（那个必须要做）。
4. **把应用加进这张表**：飞书表右上角「⋯ → 更多 → 协作设置 → **添加文档应用**」，把这个应用加进去并给编辑权限。
   ⚠️ **这步也最容易漏**，而且和第 3 步漏了报的错**长得一模一样**。两个都做了才算通。
5. **在扩展里填** → 先点「**测试连接**」（会真写一条探针记录、逐字段读回来比对、改一次状态、再删掉），通过了再点「保存」。

> 开放平台那几步只能你自己操作（App Secret 只存在你的账号里）。
> 「测试连接」失败时，扩展会把飞书给的**「申请权限」直达链接渲染成可点的**，直接点开就能去补权限。

之后勾上开关就自动同步了。改动之后**延迟几秒**才推 —— 这是故意的，连着拖三个任务只会合并成一次写请求，为的就是避开上面那个并发写冲突。

### 底表在哪（v0.6.6 起不用去飞书里翻）

**v0.6.7 起这一行的两个按钮一定点得动。** 如果它说没查到网址（你的应用没开云文档读权限时会这样），把飞书里那张表的链接粘到上面「已经有表了」那一栏**一次**，扩展就记住了，之后直接跳。

设置页「同步」按钮下面会多出一行 **「底表」**：

- 左边是**表名**加上 Base token 和数据表 ID 的短串 —— 一眼就知道同步进了哪张表；
- 后面跟着**飞书表里现有多少条记录**，跟着每次同步刷新（这就是你核对「到底同没同步过去」最快的方法）；
- 右边两个按钮：**「在飞书打开」**（直接跳到那张数据表，链接里带 `?table=`，不会落在别的表上）、**「复制链接」**。

> 为什么值得专门做这一块：**一张多维表格里可以有好几张数据表**，飞书网页打开时默认落在第一张上，而扩展读写的是配置里指定的那一张。曾经出现过「扩展说同步成功了，打开飞书却什么也没有」——就是落在了另一张表上。现在目标直接摆出来，不用猜。
>
> 表名和网址是在「创建多维表格」时自动记下的；手动接表的话，把整条链接粘一次进设置页，它就会记住，之后这一行也能用。手工改过 Base token 之后，旧网址会自动作废（按钮变灰并提示你重新粘一次），免得把你领到旧表上。

### 升级会不会吃掉我的数据（答：不会）

三个常见疑问，一次说清：

| 疑问 | 答案 |
| --- | --- |
| **必须换这个扩展包才能迭代吗？** | 改界面、改文案、改逻辑，都是**把文件覆盖进原来那个目录 + 回扩展管理页点一下「刷新」**，不用重新装、更不用换目录。发新包只是为了给同事。 |
| **我新增了数据，后续更新会覆盖掉吗？** | **不会。** 任务数据存在浏览器里属于这个扩展 ID 的空间中（`chrome.storage.local`），跟代码文件无关。覆盖文件只换了「程序」，没碰「数据」。 |
| **更新时要重填 App ID / Base token 吗？** | **不用，全自动继承。** 那四项凭据和任务、项目存在同一个地方，升级后原样还在。这正是 v0.6.3 加固定扩展 ID 的目的（详见第一节「以后怎么升级」）。 |

唯一会丢数据的三种情况，避开就行：① 在扩展管理页点的是**「移除」**而不是「刷新」；② 在浏览器里清了「站点/扩展数据」；③ 有人把 `manifest.json` 里的 `key` 删了（删了之后扩展 ID 会跟着目录走）。另外 v0.6.3 起每次版本号变化都会**自动留一份旧数据备份**，设置页「数据」里能一键恢复。

### 冲突了怎么办：飞书赢

两边都改了同一条任务时（比如你在飞书改了标题，扩展这边同时改了备注），规则是**飞书的版本赢**，本地的改动会记进一份**冲突日志**里，在设置页能看到是哪几条、本地原本是什么。

为什么不反过来？因为**专程跑到飞书去打字的动作，意图比在扩展里顺手拖一下明确得多**。但无论是哪边赢，都**不会静默丢掉**——冲突会明明白白摆给你看。

### 删除有个安全阀

如果扩展发现飞书上「一下少了一大半记录」，它**不会照做**，会在设置页报警并停在那儿等你确认。因为分页拉取失败、权限被改这类问题，也会表现为「记录大批消失」，照做等于一键清空你的表。确认是你要删的，再点「确认删除」。

### App Secret 存在哪（这是个权衡）

**App Secret 是明文存在你本机浏览器的扩展存储里的。** 这个必须说清楚：

- 它是你这台电脑上的一个本地文件，**扩展不会把它发到飞书以外的任何地方**（网络请求只打 `open.feishu.cn`）。
- 但同机器的其他程序、或者拿到你电脑的人，理论上能读出来。所以**用一个专为此事建的应用**，别拿公司主应用的凭据来填。
- 权限也给到最小：只开多维表格读写，别的都别开。真泄漏了，别人也就能动你这几张表。
- 不放心就不填。**不接飞书，扩展一条网络请求都不发。**

## 七、桌面上的球：两种，一种零安装

| | **网页上的那颗**（默认，零安装） | **桌面程序那颗**（可选） |
| --- | --- | --- |
| 怎么来 | **什么都不用装**，装完扩展打开网页它就在 | 双击一次 `install.cmd` |
| 形状 | 真·圆形、**真透明**、32px、平时半透明 | 真·圆形、真·透明 |
| 待在哪 | 贴着**网页**的左右边缘、垂直居中，可拖走 | 浮在所有**窗口**最上层，可拖到任何角落 |
| 点一下 | **记一笔**（输入框当场出现） | 展开成迷你任务列表 |
| 自动收起 | 点页面别处就收起 | 有（鼠标移开就收） |
| 跨浏览器 | 有（Chrome / Edge / Tabbit 都行） | 有 |
| 数据 | 同一份 | 同一份 |

**两份数据是一条通道**：两种球都**不存任何东西**，只读扩展里的那一份；装哪个、装不装，都不影响任务本身。

### 7.1 网页上的那颗（零安装，推荐先用这个）

**打开任何一个网页，它就在那儿** —— 不用点任何东西。默认贴在**屏幕右边缘、垂直居中**，球面上是未完成数。

| 想干什么 | 怎么做 |
| --- | --- |
| **记一笔** | **点一下球** —— 输入框当场出现，打完字按 `回车`。存下后球上闪一个白勾 |
| 不记了 | 按 `Esc`，或者点页面任何别处 |
| 挪个地方 | **按住球往别处拖**，松手会自动吸附到**最近的那条边**（左右按球心过中线判定） |
| 进设置 | 鼠标移到球上，球**内侧**会露出一个小齿轮，点它 |
| 看完整任务台 | 点浏览器右上角的**扩展图标**（那里本来就是完整的任务台） |

**三条要知道的**：

- **重载扩展之后，已经开着的标签页要刷新（F5）一次才会长出球** —— 这不是坏了。声明式 content script 只在**页面被打开时**注入（官方原文 "used every time a page is opened"），扩展重载**不会回溯注入**已经打开的页面。
- **它平时半透明、而且避开正文** —— 只在左右两边、垂直居中，加上半透明和「点别处就收起」，基本不挡东西。全屏看视频 / 看图片时它会自己藏起来。
- **它需要「读取和更改你在所访问网站上的数据」这个权限** —— 这是 content script 注入的固有代价（球就是你正在看的那个网页里的一个元素）。

> v0.14.0 把球从「三层」砍到了「一层」：以前是鼠标移上去滑出竖向滑块 → 点开迷你列表 → 才到输入框，现在点球**直接**就是输入框。参考的是竞品「轻氧翻译」（开源）的骨架 —— 球贴边半透明、悬停只多一个小圆钮、**点球直接执行主功能**。
> ★ **v0.24.0 尾**：最后那个「悬停才露的小齿轮」也删掉了 —— 它点了就是打开设置页，
> 而球的旁边**不该再多出任何东西**（老大看过真机截图后点名）。删的时候结构（那段 markup）、
> 样式（那一段 CSS）、行为（那个 click 绑定）**三处一起走**：只删样式的话按钮还在 DOM 里
> （看不见，但能被 Tab 聚焦、能被点上、读屏软件还会念出来）；只删结构的话那段 CSS 变死代码。
> 进设置页的入口没有消失 —— 走扩展图标 → 弹窗里那两处。

### 7.2 桌面程序那颗（可选，想要真圆形+真透明再装）

**不装它，前面所有功能（含 7.1 那颗球）一点不受影响** —— 它是纯加分项。

它为什么得单独装：球要的五件事 —— **透明、无边框、圆形、全局置顶、不进任务栏** —— 全部归**操作系统窗口层**管，而浏览器扩展的 API 天花板在**浏览器窗口层**，够不着。官方对「扩展能不能做透明窗口」的答复原话就是 `No, this is not possible in an extension.`（7.1 那颗球绕开这五件事的办法，是用画中画窗口换掉了「透明 + 圆形 + 自动收起」。）

所以这颗球是**一个独立的桌面程序**，扩展靠浏览器官方的「原生消息传递」（native messaging）跟它说话：

```
扩展的后台  ──"com.taskboard.ball"──>  桥接程序 host.exe  ──本机回环 TCP──>  球
```

**全程在这台电脑里转，一个字节都不出门。** 中间那个 `host.exe` 不是多余的：浏览器拉起原生宿主时只给它 stdin/stdout 两根管子，得有个小东西把管子接到球的端口上。它只有 200 KB，**不解析内容、纯转发**。

### 7.2.1 怎么装

1. 拿到那个分发包（和扩展不是同一个 zip，里面是 `install.cmd` + 两个 exe + 这份说明）。
2. 双击里面的 **`install.cmd`**。
3. 看到「安装完成」就行了。

它做三件事：把两个 exe 复制到 `%LOCALAPPDATA%\TaskBoardBall\`、写一份宿主清单、在注册表里登记一下 —— **用户级，不需要管理员，不需要重启浏览器**。

装完想确认一下（`install.cmd` 里已经替你跑了一遍，结果打在屏幕上，也写进了同目录的 `install.log`）：

```
taskboard-ball.exe --verify
```

哪天不想用了：

```
taskboard-ball.exe --uninstall
```

> 卸载只**反注册**，不删 `%LOCALAPPDATA%\TaskBoardBall\` 里的文件 —— 半删的安装比全在的更糟。想彻底清干净，反注册完自己把那个文件夹删掉。

### 7.3 怎么确认它连上了

设置页 →「**桌面悬浮球**」。那里有一个状态点、两句话、两个按钮（「测试连接」「立刻同步到球」）。

- **绿点「已连上」** —— 扩展和球正在对话。
- **灰点「没连上」** —— 下面那行会写**原话**。别忽略它，照着看：

| 那行写的是 | 意思是 | 怎么办 |
|---|---|---|
| `Specified native messaging host not found.` | 桥接程序没装，或者注册表指错了地方 | 双击 `install.cmd` 重装一次 |
| `桌面悬浮球没有在运行` | 装好了，但球没开 | 双击 `taskboard-ball.exe` |
| `球桥没加载` | 扩展目录里少 `ball.js` | 回第二节确认那 14 个文件都在 |

> **为什么这里显示的是英文原话而不是一句「连接失败」**：上面这三种是完全不同的问题，翻译成同一句话就等于把线索扔了。留原话是刻意的。

### 7.4 球上有什么、没有什么

**有的**

- **球面上是未完成数**（挂起和已完成都不算）。显示 **`–`** 的时候意思是「扩展没连上，我还不知道」—— 它**不会**给你看 `0`，因为「不知道」和「真的没有」是两件事，混了就会让你以为任务全没了。
- **点一下展开成迷你列表**：待办在前、完成的沉底，最多 40 行；每行左边一个圆圈，点一下就 **todo → doing → done → todo** 转一圈。
- **底部那行直接记一笔**：写完按回车就进任务台，日期是**今天**、项目用**上次用过的那个**。球上不给选项目 —— 猜错了比让你多打两个字更烦。
- **能拖到任何角落**，`Esc` 收起，再点一下又展开。

**没有的**

- 不能在球上**改标题 / 填备注 / 改日期 / 设优先级**。球是「抬头看一眼 + 顺手点一下」的地方；认真改一条，还是回弹窗或者大编辑抽屉。
- 不能在球上把任务**改成挂起**。挂起是一个判断（「这事先不占我的心力」），不该藏在一个圆圈的三档循环里。
- 球**不存任何数据** —— 它没有自己的库、没有 localStorage。所以**关掉浏览器之后，球上就只剩一句「没连上扩展」**。这是设计，不是故障：宁可说「不知道」，也不给你看一个过期的数字。

## 八、装完自查（30 秒）

装好后确认这几件事，有问题再找我：

0. **先确认按钮是活的**：点顶部「按项目」，高亮应该跟着跑；点卡片右上角的 `×` 能把任务删掉。如果所有按钮都没反应，说明装错了版本
1. 点工具栏的任务台图标 → 能弹出 560×580 的小窗，光标已经在输入框里
2. 输入「测试」回车 → 待办列出现一张卡片
3. 顶着卡片往右拖到「已完成」列 → 卡片过去了，已完成计数变成 1
4. **再建一张，拖到最右边那条紫边上** → 卡片消失、紫边上的数字变成 1、底栏出现「1 项已挂起」；点紫边能展开浮层看到它，点一下卡片能放回待办
5. 点一下卡片 → 变成可编辑状态，改完按回车（或点别处）保存
6. 按 `Ctrl+Shift+L` → 弹窗能关掉再打开
7. 图标上有没有显示未完成数量（挂起的不算）
8. **（只在接了飞书时做）**：设置页点「测试连接」，应当六步全绿；然后在弹窗里建一条任务，等十几秒，去飞书表格里刷新看有没有出现；再在飞书里把它的标题改掉，回扩展看有没有跟着变

**第 3、4 步（拖拽）是最需要手测的**。自动化测试跑不了拖拽的落点判定（测试环境没有真实的布局引擎，`getBoundingClientRect` 全返回 0），所以这两步只能人眼确认。

**第 8 步同理必须手测**：自动化测试用的是「假的飞书接口」（能验证同步逻辑，验证不了真实鉴权和网络）。真实鉴权只有你自己填的那份凭据能跑。

### 五条不能踩的线

> ⚠️ **一、脚本必须写成独立的 `.js` 文件，用 `<script src="...">` 引进来。**
> 浏览器扩展的安全策略（MV3 CSP）**禁止执行 HTML 里内嵌的 `<script>` 内容**，也禁止 `onclick="..."` 这类写在标签上的事件。违反了不会报错提示你，只会「界面正常显示、所有按钮全哑巴」。而且这条策略**不允许放宽**，写进 `manifest.json` 反而会让扩展直接装不上。
> 顺带一提：自动化测试用的 jsdom 环境**不检查这条策略**，所以「测试全绿」不代表「装进浏览器能用」，改完务必真机点一遍。

> ⚠️ **二、别给卡片写 `--tint` 的默认值。**
> 卡片的状态色是从所在的列（`.col` / `.holdfly`）继承下来的。CSS 里元素自身的声明优先级高于继承，所以只要在 `.card{}` 里写一句 `--tint:...`，挂起浮层里的卡片就会全变成灰的。要兜底请用 `var(--tint, 152,160,173)` 这种兜底写法。

> ⚠️ **三、同步只能在一个地方跑（`background.js`），别在 popup / manage 里直接调。**
> 飞书同一张表**不支持并发写**。如果弹窗和后台同时往同一张表写，就会撞 `1254291 Write conflict`，两边都失败。所以弹窗和设置页只负责**发消息**（`sync-now` / `sync-selftest` / `sync-wake`），真正的同步动作一律由后台执行。
> 顺带：MV3 的后台是「用完就被回收」的，`setTimeout` 不保证能活到点。所以延迟推送配了**两道 alarm 兜底** —— 改动后几秒的一次性叫醒（`armSoon()`），加每 5 分钟一次的周期兜底。**两个都别删**：只有周期那个的话，你加完任务最多要等 5 分钟才推上去，看起来就跟「同步失效」一样。

> ⚠️ **四、写飞书时别带 `ignore_consistency_check=true`。**
> 这个参数是官方给「同表写冲突 1254291」开的性能后门，看起来很适合我们（批量推记录）。但官方文档同时写明：开了它**就不保证读写一致**（"可能会导致某些节点的数据不同步，出现暂时不一致"）。扩展的整条链路都是**写完立刻要读**（测试连接读回比对、自检改完状态读回、你推完马上打开飞书看），一开这个参数就会到处报「写进去了但读不回来」。我们的写入量本来就小（CHUNK=100 + 块间 500ms），不需要靠它提速 —— **永久关掉**。

> ⚠️ **五、浮窗里只能用同源 iframe 装 `popup.html`，别想往浮窗的 document 里注入扩展脚本。**
> 画中画窗口的 document **origin 是 `null`**（实测：`location.href` 是 `about:blank`、`origin` 是字符串 `"null"`）。往里插 `<script src="chrome-extension://…">` 看着能跑，其实那个脚本拿不到扩展上下文 —— `chrome.runtime` 是 `undefined`，`chrome.storage` 也是，真机跑出来的第一句报错就是 `Cannot read properties of undefined (reading 'id')`。
> 正确做法是 iframe：`<iframe src="chrome-extension://<id>/popup.html?pip=1">`。iframe 里的文档是一张**正经的扩展页** —— `chrome.runtime.id`、`chrome.storage`、`chrome.windows` 一应俱全，整套任务台零改动复用。
> 顺带一条相关的坑：**`requestWindow()` 的 `copyStyleSheets` 选项已经从规范里删掉了**（官方原文：「在旧版规范中受支持。现在，情况已不再如此」）。传进去不报错、也不生效，表现只有一个 —— 「浮窗里样式全丢」。样式得自己写进浮窗 document，或手动遍历 `document.styleSheets` 复制。

改完文件后，去扩展管理页点任务台卡片上的「🔄 刷新」按钮生效。

## 十、已知边界（v0.15.0 的）

- **图标只有一种底色**：克莱因蓝圆角方块 + 白色「任」，没做多套主题切换。
- **没有重复任务**：每天例行的任务得手动重建。
- **开始日和截止日没分开**：只有一个 `date` 字段，用来排序和「今天」筛选。
- **没有子任务**。（优先级 v0.7.0 已经做了，见第四节。）
- **没有完整的每周回顾**：v0.9.0 只在底栏给了「本周完成 N 件」这一个数字 —— **没有趋势图、没有连续天数、没有按项目的完成统计**。
- **备注只是纯文本**：没有富文本、没有待办清单、没有附件。就地编辑里能往下拉高、大编辑里会自己长高到 196px，但**不做 Markdown 渲染**。
- **键盘流还差几步**：不能用键盘把任务**拖到挂起**，也不能用键盘**一次改多条**（选中多张一起改状态/日期/项目）。大编辑抽屉能用 `e` 开、`Esc` 关，但**抽屉里面改「项目」还是得用鼠标点**那个下拉。
- **浮到桌面做到了，但那颗球已经没有入口了**：v0.10.0 已实现「浮窗置顶 + 可拖 + 可缩放 + 关掉自动收拾」，v0.14.0 又把弹窗里那个按钮删掉了。**做不到的**：① 开机自启（扩展没有这个能力）；② 浮窗坐标**只由系统记着，扩展读不到也改不了**，所以做不了「跟随指定显示器」「在设置里存坐标」这类功能。想手工试它，地址栏打开 `chrome-extension://<扩展ID>/host.html` 即可。
- **两种球，各有各的做不到**（见第七节）：
  · **网页上的那颗**（零安装，v0.14.0）：**只活在网页上** —— 切到桌面、微信、Excel 就看不见了（它是个网页元素，不是窗口）。它只要「读取和更改你在所访问网站上的数据」这一个权限（content script 注入的固有代价）。另外**重载扩展之后，已经开着的标签页要刷新（F5）才会长出球** —— 声明式 content script 只在「页面被打开时」注入，不会回溯。
  · **桌面程序那颗**（可选，要装一次）：透明 / 无边框 / 圆形 / 全局置顶 / 不进任务栏这五件事全在**操作系统窗口层**，扩展够不着，所以它只能是个**独立的桌面程序**。由此两条限制：① 得**单独装一次**（双击 `install.cmd`）；② **两个都得在**才看得见数据 —— 只开浏览器不开球，球上不会有事，但扩展侧的状态点会显示「球没开」。
- **网页球的交互只有一层**（v0.14.0 定的）：点球就是「记一笔」，**没有第二层**。之所以能这么简：官方明文只要设了 `default_popup`，`action.onClicked` 就不会触发 —— 所以「点图标直接出球」在浏览器层面根本做不到，零点击只能靠注入网页这条路。
- **球上只能「看」和「点一下」**：不能改标题 / 备注 / 日期 / 优先级，也不能把任务改成挂起。要动内容就回弹窗或大编辑抽屉。
- **球上的数字最多显示「99+」**：球面只有 32px。想看确切数字点扩展图标（角标上也是未完成数）。
- **自然语言只认固定写法**：「下个月」「国庆前」「三天内」这类**不做** —— 它只认第四节列出来的那些词。另外它只摘「最先出现」的那个日期候选：写「下下周三」不会先被「下周」抢走，但一句里写两个日期只有第一个算数。
- **列内顺序**：显式「排序序位」→ 优先级 → 视图原本的规则（待办按日期、已完成按完成时间倒排）。想要绝对顺序就去飞书表里给那一行填「排序序位」。
- **挂起不能设自动到期**：挂起的事不会自己回来提醒你，得偶尔点开看一眼。
- **归档没有单独的页面**：归档的任务在看板的任何视图里都看不见，只能从**弹窗底栏的「归档 N」**打开那份只读清单，在里面**逐条**取回（v0.8.1 起；以前是一次全倒回来）。设置页「数据」区会显示「已归档 N 条」并告诉你去哪儿取回（它们的数据一直都在，导出 JSON 里能查到）。
- **弹窗窗口的圆角做不了**：窗口外形由浏览器绘制，扩展侧改不了（官方 issue 状态 Won't fix）。所以弹窗是**直角边到边**的；被当标签页打开时才有圆角。
- **搜索只匹配标题和备注**：不搜项目名、不搜链接。**不支持 `关键词1 关键词2` 这种多词组合**，一整串当一个词来匹配。
- **导入导出必须在设置页做**：弹窗只要一弹文件选择框就会失焦关闭，所以这类操作没法放在弹窗里。
- **跨浏览器数据不自动同步**：Chrome 和 Tabbit 各存各的，靠导出导入搬运。**接了飞书之后这条有救**——两边填同一张表的凭据，就都镜像到同一个地方了（但仍不是实时互通）。
- **飞书那侧是镜像，不是主库**：断网时本地照常用，联网后自动补推。
- **同步是「整条记录覆盖」而不是「逐字段合并」**：同一条任务两边都改，飞书赢，本地那份改动进冲突日志（不会静默丢）。
- **同步的最小单位是「本地 id」**：在飞书里手工新建的记录会被拉下来并分配一个新 id。`本地ID` 这一列是两边对上的钥匙 —— 手改它会让两条记录各自认成一条新任务。**v0.6.6 起有兜底**：就算那一格被清掉了，扩展也能按记住的 record_id 把关系补回来，不会再凭空多出一条重复任务。
- **记录数上限 20,000 条**（飞书多维表格的限制，自用够得很）。
- **「一键创建」建出来的表，所有权归应用**：那张表躺在应用的云空间里，你是「被共享的人」而不是主人。要去飞书「云文档 → 共享给我的」里找它。**想让表完全属于自己，就走路线 B 手动建。**
- **「一键创建」只需要 `bitable:app` 一项权限**，没有额外要求。
- **想让链接分享设置成功**，应用可能还需要一项云文档类权限（比如「查看、评论、编辑和管理云空间中所有文件」）。**这项是可选的** —— 不开的话表照样建好、同步照样跑，只是你在飞书网页里打开它只能看。真需要时报告里会写出来。
- **毛玻璃在极老的浏览器上会退化成半透明白**：`backdrop-filter` 不被支持时视觉会朴素一些，功能完全不受影响。

## 十一、出问题了

- **快捷键没反应**：去 `chrome://extensions/shortcuts`（Tabbit 同路径）看看 `Ctrl+Shift+L` 是不是被别的扩展占用了，是的话在那页改一个。
- **界面能看见但所有按钮都点不动 / 管理页标了「错误」**：装到了 v0.4.0 那个坏包。根因是内联脚本被扩展的安全策略拦掉了。换成 v0.11.0（**注意是覆盖文件后点「刷新」，不是点「移除」** —— 点移除会连带清掉本地数据）。
- **按 `1` `2` `3` 没反应 / 在输入框里打字突然跳走了**：先对照第三节那张键位表。键盘流**只在没在输入的时候生效**，如果光标在搜索框或备注框里，这些单键是打不出来的（这是刻意的）。真正没反应的场景通常是：浏览器把焦点给了别的地方（比如你刚点过页面上的别处），点一下弹窗里任意位置再按即可。
- **按 `e` 没反应 / 大编辑打不开**：和键盘流是同一个前提 —— **只在没在输入的时候生效**。如果光标停在搜索框或备注框里，`e` 是打不出来的（这是刻意的）。另外 `Esc` 是**后进先出**的：抽屉、下拉、改期面板开着时，第一下先收最上面那一层。
- **写了「明天」，日期却没变成明天**：去设置页「填写」看一眼那个开关 —— 关掉之后所有文字都原样当标题，不做任何解析。这种情况**不会有任何提示**，是设计如此（关掉就是「别猜我的意思」）。
- **网页上没有那颗球**：先**刷新（F5）一次**。声明式 content script 只在「页面被打开时」注入，**重载扩展不会回溯注入已经开着的标签页** —— 这是「球不见了」最常见的原因，不是坏了。刷完还没有，就去扩展管理页确认它处于启用状态。
- **点球弹出来的输入框里写着「还没读到浏览器里的数据」**：说明它还没拿到 `storage` 里那份数据（这时球面上的数字会是 `–`，意思是「我还不知道」，不是「一件都没有」）。切到别的标签页再回来，或者按 F5 刷一次。
- **「浮到桌面」那个按钮去哪了**：v0.14.0 删了 —— 它就是「点两次」的来源，而球已经搬到网页上（打开网页它就在）。`host.html` / `host.js` 那份画中画实现还在包里，想手工试就地址栏打开 `chrome-extension://<扩展ID>/host.html`。
- **浮窗找不到 / 一闪就没了**：先确认浏览器内核 ≥ 116（画中画文档 API 的要求；任务台本身不受影响）。另外浮窗**不在任务栏里** —— 它是独立置顶的小窗，关掉的方式就是点它自己的 ×；它也不会随浏览器最小化而消失（这是它存在的意义）。
- **关掉浮窗后任务栏里还剩一个小窗**：正常情况下会自动退场。万一没退，右键那个小窗 →「关闭窗口」即可，不影响任何数据；下次手工打开 `host.html` 会重新开一个。
- **图标点了没反应**：确认扩展是启用状态；再确认浏览器版本 ≥ 116。
- **快捷键打开的是标签页而不是弹窗**：说明这个浏览器不提供 `action.openPopup`，属于预期内的降级，功能不受影响。
- **右键没有「把当前页存到任务台」**：重新加载一次扩展（扩展管理页 → 刷新按钮）。
- **拖不到那条紫边上**：紫边很窄（36px），拖的时候盯着看它有没有亮起来（外圈变紫＝已对准）。对准了再松手。
- **挂起的东西找不到了**：点一下最右边那条紫边，浮层会列出**所有**挂起的任务。窄条上的数字是全部挂起数，不随视图变化——它是停车场，不该因为你切了个视角就把事藏起来。

### 飞书同步相关的

- **测试连接报 403**：三个原因长得都很像，逐个查——① 开放平台上没给这个应用开「多维表格」权限；② 开了但**没创建版本并发布**（权限不发布等于没开）；③ 前两步都做了，但**没把应用加进那张表**（表格「⋯ → 更多 → 协作设置 → 添加文档应用」）。②③ 最容易漏。
- **报 `99991672`（提示里带「应用尚未开通所需的应用身份权限」）**：就是上面 ① 或 ②。报错里那句 `One of the following scopes is required: [bitable:app:readonly, bitable:app, ...]` 是飞书在告诉你缺哪个 scope。**要开的是 `bitable:app`**，不是 `bitable:app:readonly`——只读的话「读数据表」能过，后面「写记录/更新/删除」会连续失败。v0.6.1 起，报错里的**「申请权限」链接可以直接点**，点开就是勾好 scope 的申请页。
- **报 `1254068 URLFieldConvFail`（写入/更新记录时）**：飞书「链接」这一列是**超链接类型**字段，值必须是 `{link, text}` 对象，传裸 URL 字符串会被拒。**v0.6.2 已修**（v0.6.1 及更早会把裸 URL 发出去）。如果你自己重建过这张表，确认「链接」列建的是**超链接**类型；建成了纯文本列也会出问题。
- **读表能过、写记录失败**：典型的只开了 `bitable:app:readonly`。回开放平台把 `bitable:app` 也加上，再创建版本并发布。
- **报「字段不存在」之类**：字段名和飞书表里**不是逐字一样**（多一个空格、换行、全角半角都算）。对一遍第六节那张表。
- **报 1254291 / 1254607**：写冲突或数据没准备好。正常会自动退避重试；如果频繁出现，说明有别的东西在同时写这张表（比如另一个浏览器也配了同一张表）。
- **记录大批消失报警了**：这是安全阀在拦。先确认是不是你自己删的。是误报（比如刚清空重来）就点「确认删除」放行。
- **飞书里新建的记录没同步下来**：确认新建时没手填 `本地ID`；然后点一下「立即同步」。
- **改了飞书但扩展没变**：扩展默认是「打开弹窗时如果距离上次同步超过 1 分钟才拉」，所以改完飞书稍等一下再开弹窗，或直接点设置页的「立即同步」。
- **同步状态一直转圈**：可能是 App Secret 填错了（token 拿不到）。重新点一次「测试连接」，它会明确告诉你是卡在哪一步。
- **「测试连接」里写进去了、却报「读回并逐字段比对」失败（v0.6.5 及更早）**：根因是写请求带了 `ignore_consistency_check=true`，飞书官方写明它会**牺牲读写一致性**（"某些节点的数据不同步，出现暂时不一致"）。写是成功的、数据也在，只是**那一瞬间读到的还是旧副本**，而后面「更新记录 / 删除记录」两步都依赖这次读回，于是一起报同一句「刚写进去的记录读不回来」。**v0.6.6 已修**：去掉了那个参数，并且自动重试一次读回。
- **提示「同步成功」但飞书里看不到记录（v0.6.5 及更早）**：先别怀疑数据丢了。三个方向按顺序查——① 打开飞书表时**看左边选中的是哪张数据表**（一张多维表格可以有好几张表，飞书默认落在第一张上）；② v0.6.6 起设置页会写明「底表」是哪张、里面有多少条，直接点「在飞书打开」；③ 老版本同样受上面那个一致性参数影响，推上去的记录可能几十秒后才在网页里可见。**v0.6.6 还修了一个更硬的坑**：换过表（或表被重建、有人在飞书删了记录）之后，那些任务的「本地↔远端」映射会失效，旧代码会**静默跳过它们**，状态显示「已同步」但永远推不上去 —— 现在会按本地内容重新推，并在报告里写明「重建 N 条」。
- **设置页「在飞书打开 / 复制链接」点了没反应（v0.6.6 及更早）**：如果你是在 v0.6.6 之前建的表，配置里没存网址，老代码会把这两个按钮置灰 —— **灰按钮不吃点击**，所以看起来像坏了。**v0.6.7 已修**：按钮不再禁用，点击时自动去飞书查一次，查到还会记下来。
- **「同步成功」但你可能有不止一张同名表**：⚠️ 「一键创建多维表格」是**新建一张**多维表格，不是塞进你原来那张。所以如果你习惯打开旧的那张，就会觉得「什么都没同步过去」—— 其实数据全在新表里。**认准设置页「底表」那一行**：它写着扩展真正在读写的那张表（表名 + base/表 id + 现有条数），点「在飞书打开」一定落在对的表上。那一行的条数也是核对「到底同没同步」最快的方法。
- **状态里出现「重建 N 条」**：意思是这 N 条任务在飞书表里找不到对应记录了（换过表 / 表被重建 / 有人在飞书删了），扩展按本地内容把它们重新推了上去。**你的本地数据一条没动。** 如果这个数字反复出现，说明有另一个浏览器或同事在同时删这张表里的记录。

## 十二、看板（设置页左边第五项）

设置页左导航点「**看板**」。它读的就是你本地那份数据，**不发任何网络请求**。

四块：

| 块 | 看什么 | 口径 |
| --- | --- | --- |
| 顶部 KPI | 在手 / 今天完成 / 本周完成 / 平均完成周期 | 「在手」＝未完成且未归档，跟设置页顶上那行统计**同一个口径** |
| 状态分布 | 四列各有多少条（未开始 / 进行中 / 已完成 / 挂起） | 只算**在手**的，归档的不进图 |
| 项目排行 | 每个项目压了多少在手任务 | 按条数从多到少；没项目的归到「未归类」 |
| 近 7 天趋势 | 每天新增多少、完成多少 | 按完成时间（`doneAt`）落在哪一天算 |

三个要知道的点：

- **「平均完成周期」在一条都没完成时显示 `–`，不显示 `0 天`。** `–` 是「不知道」，`0` 是「真的是 0 天」——
  两件事。老规矩，看板也不例外。
- **图是手写 SVG，不是图表库。** MV3 禁止远程脚本，所以库得打进包里；Chart.js 一家就约 200KB，
  跟现在整包差不多大。这四张图用不上那 200KB。
- **数字都用等宽数字（`tabular-nums`）排版。** 不等宽的话，刷新时「7」比「1」宽，整行会左右抖一下。

## 十三、AI 大模型（可多个配置）

设置页 **AI 能力 → AI 大模型**。

- **它管的是「云端」那一路。** 上面的「在哪跑」选**仅本机**还是**云端**；选云端时，具体走哪个模型由这个列表里的**选中项**决定。

- **API Key 只写在本机浏览器里**，不进导出文件，也不上传到任何地方。窗口上那行盾牌提示就是这么个意思。

## 十四、亮 / 暗主题

**右上角那颗开关**（设置页在页面右上；弹窗里它在顶栏，跟搜索框同一行）。

- 点一下就切。**第一次点之前，它跟着你的系统设置走**；点过之后，系统再变也不跟了（你表态了）。
- 切换时有一圈**从开关位置扩散**的圆动画。浏览器不支持这个能力的话就直接切，功能一样完整。
- **首帧不会闪白**：主题在页面开始渲染之前就定好了，不存在「先白一下再变暗」。
- 两页都吃这套变量：弹窗、设置页、看板、AI 大模型窗口，没有一处是只在亮色下好看的。

### ★ 两态是两套变量：改一处必须想另一处（v0.18.0 的教训）

这一轮真机验收抓出两个**只在亮色（或只在暗色）下才看得见**的回归。都不是逻辑错，是**变量**错：

| 症状 | 真因 |
| --- | --- |
| 亮色下卡片没底、浮层透明、边框全丢 | 引用点搬进了页面（`var(--card)` 这类），定义点却漏在 `theme.css` 的**亮色块**外 —— 只写在暗色块里。**无兜底的 `var()` 找不到定义时，整条声明回退到 `initial`**（不是「用了个默认值」）：`background` 这种简写会整个失效，实测 `backgroundImage:none`。同一批共 36 处引用一起中招。 |
| 暗色下高优先级标题几乎看不见 | 亮色那套 `--p-high` 是 `#101216`（近黑），暗色仍用它 → 压在同色系的卡片上只有 **1.16:1**，而「普通」那档反而看得清，**层级整个反过来**。 |

所以两条口径：

- **暗色不是「把亮的反过来」，是「重新排一遍层级」。** 亮色下「越深越重要」，暗色下必须「越亮越重要」；不覆盖就等于反转。
- **页面里每个无兜底的 `var()`，亮色和暗色都必须有定义。** 这条现在有两道门盯着（`_validate.py` 读开发目录、`_pack.py` 读**包内容**），另有变异 M19／M20 常驻，证明它们真的会红。

### ★ 还有一种坏法：那个色**压根没写成变量**（v0.19.0 的教训）

上一节的两道门都只检查「**页面引用了哪些 `var()`**、这些键有没有定义」。如果某个文字色是**写死的 hex**，那它根本不在体系里 —— 不是「漏覆盖」，是「门都不知道它存在」，可症状一模一样：暗色下那个色不跟着切。

v0.19.0 收官前扫了一遍两页的 `color:` 声明，抓出 `popup.html` 里 13 个写死的文字色，其中 4 个常驻可见、贴在**卡片**上 —— 而卡片正是这一版大改的构件（底从实面变成玻璃 + 液态斑 + 噪点），同一个灰字落在不同色斑上，对比度还会跟着斑走。那 4 处已接进变量（`--ink2` / `--accent` / `--s-hold`），并加了一道门（`_validate.py` 13h）盯着「卡片上常驻的文字色不许写死 hex」。

★ 顺带修好一个**只在亮色下才炸**的隐患：`--accent` 原本只在暗色块里定义过。谁要是在亮色下用 `color:var(--accent)`，那条声明会**整条回退到 `initial`**（继承父级色）—— 而在此之前没人引用过它，所以任何一道门都看不见。

### 开关的「点两次回原位」

扩散动画进行中连点两下，也必须回到原位。所以判断「用户想切到哪一档」认的是**落盘的偏好**，
而不是页面上那个 `data-theme` 属性 —— 动画回调要等一帧，那一帧里 DOM 还停在旧主题。
**存储是状态、DOM 是视图**：判断意图只认状态。
